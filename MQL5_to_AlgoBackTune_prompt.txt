===================================================================

===================================================================
Equity write protocol
===================================================================
- At the END of bar b, set equity[b] = balance (after all ticks of that bar, optionally AFTER closing positions).
- For bars with zero ticks, still write equity[b] = last balance (carry-forward), or the UI equity curve will have holes.
- bars before start_bar: do not write trade/equity (indicator warm-up only).

===================================================================
Balance / PnL / commission conventions (match the engine)
===================================================================
- Entry: BUY at ask + slippage; SELL at bid − slippage; slippage = p[6] * p[0].
- At entry subtract `p[5] * lot` from balance. Commission is ALSO included in the close PnL formula below — keep both, exactly like the reference convention.
- Exit: BUY positions close at bid; SELL positions close at ask.
- Per-position PnL at close: `dir * (exit_px − entry_px) * lot * p[3]  −  p[5] * lot`.
- `balance += pnl` per closed position.
- equity[] = cash balance only (no floating P/L).
- MAE/MFE per open slot per tick:
    fav = bid − entry (longs), entry − ask (shorts)
    if fav < 0: p_mae[j] = max(p_mae[j], −fav)
    always     p_mfe[j] = max(p_mfe[j], fav)

MQL5 → Python translation rules (apply to WHATEVER the EA does)
===================================================================
A. State scan: loop slots 0..max_pos-1 (index ascending). MQL5 scans PositionsTotal()-1 .. 0 and OWERWRITES currentType/lastPrice per iteration, so after the loop the values come from the OLDEST position (slot 0 under our convention). Mirror exactly.
B. Exit logic usually runs BEFORE entry logic in OnTick — preserve that order. If the EA closes all (netProfit >= target || netProfit <= −max_dd), close ALL slots, write trades, `return`/skip entries that tick.
C. Entry logic is usually evaluated when no position is open, or per-signal. Handle whatever pattern the EA uses, e.g. per-bar closed-bar signals, crossover conditions, breakout of levels, time filters, etc.
D. Grid/Averaging logic (count slots > 0, add same-direction position when distance ≥ step from OLDEST entry): compute distance in pips using p[1]; new lot from p[?] per PARAM_SPEC mapping; respect the max-positions cap.

Indicator translations (universal cases):
- iMA(symbol, period, ma_period, ma_shift, method, applied_price): build an EMA/SMA/WMA/LWMA/SMMA array over m_open/m_high/m_low/m_close/m_* (applied_price MODE_CLOSE=PRICE_CLOSE→m_close, etc.). For LWMA use linear weights; for SMMA use RMA.
- iMACD: MACD = ema_fast − ema_slow; signal = ema(MACD, signal_period); histogram = macd − signal.
- iRSI: RMA-based RS = avg_gain/avg_loss over closed bars; RSI = 100 − 100/(1+RS).
- iStochastic: %K = (close − lowest(low,k))/(highest(high,k) − lowest(low,k))*100; %D = SMA(%K, d).
- iATR: TR = max(high−low, abs(high−prev_close), abs(low−prev_close)); ATR = RMA(TR, period).
- iBands / iCCI / iMomentum / iWPR: standard formulas, rolling windows, applied to closes/HL.
- CopyBuffer(handle, 0, shift, count, dest) onto a STATIC array: dest[0] = OLDEST of the copied window (chronological, AS_SERIES=false for indicator buffers). E.g. CopyBuffer(hnd, 0, 1, 2, arr) ⇒ arr[0] = shift-2 bar, arr[1] = shift-1 (last CLOSED) bar. For AS_SERIES=true arrays, arr[0] = NEWEST.
- Indicator warm-up: leading values are garbage (zeros / NaN equivalents). Either treat the first `period-1` bars as neutral (no trades) or use the built-in convention — rolling windows with 0.0 padding for the first period−1 bars.
- OnInit indicator handles are one-time; there is no per-tick cost issue — computing arrays over m_* in one pass at the start of simulate_range is the right Python translation (values used inside bar loop via bar index b).
- Tick-volume / spread / custom indicators: derive from tick arrays you DO have (bid/ask spread, tick count per bar) — document approximations in the docstring if any.

Trade-function translations:
- trade.Buy / trade.Buy(lots, symbol, price, sl, tp, comment) → open a buy slot at ask + slippage.
- trade.Sell → open a sell slot at bid − slippage.
- PositionClose(ticket) / PositionClose(ticket, dev) → close that slot, write trade, free slot.
- PositionModify / trade.PositionModify → update sl_or_0.0, tp_or_0.0 of an open slot ONLY (no partial realization; AlgoBackTune tracks sl/tp per position).
- OrderSend → treat as market open with the given price (convert to slot fill at that price + slippage).
- Pending orders: NOT executable on real-time ticks the same way — if the EA places pendings, document this; implement them as trigger checks per tick (buy-stop/sell-limit cross above/below level) if feasible; otherwise note "NOT TRANSLATED: pending orders" in the docstring and omit them (never fake fills).
- OrderComment / ORDER_MAGIC filters: ignore magic-number comparisons — every position belongs to this EA. Symbol filters: ignore — single symbol only.
- Time/session filters (Hour(), TimeCurrent(), DayOfWeek()): compute from m_time/t_ms via integer ms math (// 86_400_000 for days, etc.).
- Spread filters: use ask − bid at the tick.
- Lot sizing: fixed lot → p[lot_index]; risk-% sizing → qty = risk_money / (stop_pips * p[1] * p[3]); implement exactly the EA's formula with p[].

MQL5 caveats to mirror (or consciously deviate, documented):
- Static vs dynamic arrays and AS_SERIES flags.
- `double var[2]` CopyBuffer ordering (section CopyBuffer above).
